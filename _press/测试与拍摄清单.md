# 第一部分：测试

## 1. 启动，先别读档

打开 UMM 面板看 mod 列表。

| 判定 | |
|---|---|
| ✅ | 只有一条 **Dynasty Retinue & Refit  0.82.0**，状态绿灯 |
| ❌ | 出现两条 / 红字 / 状态异常 → 停，把 `UnityModManager.log` 给我 |

> 上一轮就是在这里发现「备份目录被当成第二个 mod 加载」的。UMM 认的是子目录里有没有 `Info.json`，不认目录名。

## 2. 面板长什么样

**这是你从没见过的界面**（无开发模式）。

- 不该有：批量生成 / 一键全测 / 清场 / 自动结束回合 / Dump 状态
- 该有：招募 / 舰船 / 设置 / 诊断包
- 语言应自动为中文

**带着这个问题看**：假装第一次见这个 mod，你知道下一步该干嘛吗？
把每一处「我得猜」记下来 —— 这些直接决定 README 和视频要讲什么。

## 3. 读存档 A（改名后的关键验证）

读一个**已有卫兵**的存档。

| 判定 | |
|---|---|
| ✅ | 卫兵都在、名字正常、面板「在册」数量对 |
| ❌ | 卫兵变陌生单位 / 在册 0 → **立刻停，别存盘**，告诉我 |

> 这验的是 `kgd.guard` 身份标记跨改名保住了没有。

## 4. 从零招募一个卫兵 ★最值钱的一步★

你以前都用开发区批量生成，正常招募路径没完整走过。

从头走：找到入口 → 选分型 → 确认 → 卫兵出现。

记录：
- 入口好不好找？
- 有没有前置条件（利润系数）没提示？
- 五个分型的区别看得懂吗？

## 5. 打一场

看总账正常输出、卫兵正常行动即可，不用细看。

## 6. 船坞（存档 B）

**先别急着改装** —— 见第二部分「拍摄顺序」，改装前的素材必须先拍。

## 7. 收尾检查

翻 `dynasty_log.txt`，搜：

```
找不到    缺失    ERROR    Exception    解析不到
```

重点确认：包里只有 4 个数据文件（`archetypes.json` / `plans.json` / `l10n_en.json` / `Info.json`），
没有 `items_zh.tsv` / `features.tsv`。日志无相关报错 = 它们真的不是运行时依赖。

## 存档安全

第 3–6 步会改变游戏状态。**要么全程不存盘，要么存到新槽**，别覆盖正常存档。

# 第二部分：拍摄

## 分两批，原因是版本号

UMM 面板里**版本号是入镜的**。现在是 `0.82.0`，修完体检报告的问题发版就是 `1.0.0`。
而且体检报告里「应该修」的 5 条有 4 条会改动面板外观（加确认、补英文、改文案）。

所以：

| 批次 | 什么时候 | 拍什么 |
|---|---|---|
| **第一批** | 现在，测试时顺手 | 不含面板、不含版本号的所有素材 |
| **第二批** | 1.0.0 打包后 | UMM 面板（中文版 + 英文版各一次） |

## 第一批：现在就能拍（6 组）

### ① 战斗中卫兵自主行动 ★核心素材★
- 场地要**开阔**。走廊、小房间里五个卫兵挤一团，看不出谁是谁
- 最好能拍到多个卫兵同时有行动指示器/技能特效
- 视频版：完整录一个回合，玩家不操作
- 截图版：抓一帧多人同时行动的

### ② 卫兵角色面板
- 展示等级、职业链、一身装备
- 证明它们是真实成长的单位，不是摆设

### ③ 精英卫兵
- 挑外形辨识度高的（比如圣焰净罪修女、怒火铳长）
- 报得出位阶名，视频里可以念

### ④ 招募窗口
- 五个分型并排，能看出可选性
- 利润因子进度条也拍进去（说明有成长门槛）

### ⑤ 座舰改装 —— 前 ★顺序不能错★
- 舰船**外观**：找个好机位，**记住这个机位**
- 舰船**属性面板**：护盾 / 装甲 / 撞角 / 开火次数

### ⑥ 座舰改装 —— 后
- **同一个机位**拍外观
- 同一个属性面板

> ⑤⑥ 是全片最有冲击力的一组。**没拍完 ⑤ 就别点改装** ——
> 改完想重拍得先「还原为原样」，很麻烦。

### 可选：改装后的船打一场虚空战
有现成的就拍，没有别专门去打（回合制海战节奏慢、剪辑成本高）。外观对比已经够了。

- UMM 面板全景 **英文版** → Nexus

拍之前在面板里切语言即可，不用重开游戏。

# 测试 A：卸载流程端到端

这是 1.0 唯一还没验证的东西，验的是**最要紧的那条红线**：卸载 mod 之后存档还能不能打开。

当前版本 `0.85.0`。

## 第 0 步：备份存档（不可跳过）

把整个目录复制一份到别处：

```
C:\Users\kyua805\AppData\LocalLow\Owlcat Games\Warhammer 40000 Rogue Trader\Saved Games
```

后面所有操作都在副本思维下进行 —— 万一出事，把备份拷回去即可。

## 第 1 步：造出「有东西要清理」的状态

1. 读一个存档，**另存为一个新槽**（比如叫「卸载测试」），后面全在这个槽上折腾
2. 招 **2–3 个普通卫兵 + 1 个精英**
3. 去船坞做一次改装（换成巡洋舰或大巡，换船模）
4. **存盘**
5. 确认：面板显示在册数量正确，船的外观和数值都变了

## 第 2 步：按 README 的流程清理

严格照 README 第 15 行那段走，**这一步就是在验证那段文字对不对**：

1. 面板顶部 → 点【**遣散全部**】（现在是两段式：第一次点变成「再点一次（N）」，3 秒内再点一次才执行）
2. 确认日志出现 `已遣散 N 名卫兵，复查在册 0，清理完成。`
3. 舰船区 → 点【**还原原版船模**】（同样是两段式）
4. **存盘** ← 前面两步只在内存里，不存盘等于没做

## 第 3 步：关掉 mod

1. **退出游戏**
2. 打开 UMM 面板，把 **Dynasty Retinue & Refit** 的开关关掉（On/Off 那一列）
   - 或者更彻底：把 `UnityModManager\DynastyRetinue\` 整个文件夹**移出**该目录
   - ★只改文件夹名没用★ UMM 认的是「子目录里有没有 Info.json」

## 第 4 步：验收

启动游戏，读第 2 步存的那个档。

| 判定 | 现象 |
|---|---|
| ✅ 通过 | 正常读进去；队伍里没有多余成员；座舰是原版外观和数值；`Player.log` 里没有 `JsonSerializationException` |
| ❌ 失败 | 读档卡住 / 报错 / 队伍里有读不出来的成员 |

失败的话立刻停，把 `Player.log` 保留下来。

## 第 5 步（可选但很有价值）：故意不清理会怎样

这一步决定 README 那段警告该怎么写 —— 现在那句话**没人验证过**。

1. 从**备份**里另拷一个存档出来（别用你正常玩的）
2. 装回 mod，读它，招几个卫兵，**存盘**
3. **不遣散**，直接关掉 mod
4. 读档

可能的结果有三种，写进 README 的措辞完全不同：

- 能读，卫兵消失了 → 「会丢失卫兵，但存档安全」
- 能读，卫兵变成奇怪的单位 → 「会留下异常单位」
- **读不进去** → 「存档会永久损坏」← 如果是这个，README 那段要写成红字警告
